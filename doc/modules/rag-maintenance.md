# 本地语义检索（RAG）维护

RAG 用来对聊天记录、公众号文章、朋友圈和收藏做本地语义搜索。索引完全保存在本机，不依赖云端。

## 首次建立索引

- 在「系统配置 → 数据配置」打开「启用 RAG 语义搜索」，保存并重启应用后开始。
- 首次索引会把最近 30 天的聊天记录、以及已有的公众号/朋友圈/收藏缓存写入本地索引。
- 参考量级：约 10 万条消息、近 5 万个分块，在 8 线程 CPU 上约 **18 分钟**，内存峰值约 **1.5 GB**。数据量越小越快。
- 索引进度可以在同一张卡片里看到：当前阶段、每批条数、已用时间，以及聊天记录 / 公众号 / 朋友圈 / 收藏各自的百分比。
- 索引期间可以继续使用其他功能；中途退出或重启会从已保存的进度继续，不会从头再来。

## 索引出问题时

现象：语义搜索一直没结果，或设置页显示「索引异常」。

1. **先重启应用**。多数超时或临时故障重启即可恢复，不需要重建。
2. 仍然不行，再运行离线自检，确认本机环境能正常建索引：
   - 源码：`python desktop.py --check-rag`
   - 打包版：在 EXE 同目录执行 `wx-assist.exe --check-rag`
   - 自检只在临时目录写入 1100 条测试数据，**不会修改真实索引**，结果写入 `rag-check.json`。
3. 自检通过但仍无法检索，再考虑重建索引。

## 重建索引

重建会基于 `messages.db` 快照重新生成索引。索引是派生数据，重建成功后旧索引会自动删除，不影响任何聊天记录。

**打包版（推荐）**：

1. 设置 → 数据配置 → RAG 卡片显示「索引异常」时，点「重置索引」
2. 确认后重启程序
3. 启动时自动把旧索引改名留存并开始重建，进度在设置页可见
4. 重建成功后旧索引自动删除

**源码版**：可以继续用下面的脚本，流程更完整（staging 重建 + 校验后切换）。

```powershell
# 必须先完全退出应用
python scripts/rebuild_rag.py --days 30
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--data-dir` | 数据目录，默认项目下的 `data` |
| `--days` | 聊天记录重建窗口，默认 30 天 |
| `--skip-cache` | 只重建聊天记录；公众号/朋友圈/收藏会在下次启动时重新索引 |
| `--force` | 检测到应用在运行时仍继续（危险，不建议） |

流程与安全措施：

- 先在 `data/.rebuild-<时间>/` 内完成重建和校验，**校验通过后才切换**。
- 切换过程会写 `data/rag_rebuild.json`。如果中途断电或被杀，下次运行会自动还原旧索引。
- 切换并校验成功之后，旧索引会**自动删除**，不再长期占用磁盘。
- 重建不会修改 `messages.db` 本身，只读取快照。

## 注意事项

- **不要在应用运行时重建**，否则可能争抢索引文件。脚本默认会检测并拒绝。
- 重建耗时与数据量相关，10 万条消息约 20 分钟，期间请不要关闭窗口。
- 不要手动删除 `messages.db`；索引坏了只影响语义搜索，聊天数据本身不受影响。
- 索引文件和聊天数据是分开的，重建失败可以直接回退到 `.previous-*`。
